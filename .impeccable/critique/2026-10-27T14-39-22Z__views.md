## Design Specificity Verdict

Mixed. The data model is genuinely DTI-specific (Records' field set, Tasks' Direct Admin/Department Directive/Whole Office hierarchy). The chrome is generic admin-SaaS vocabulary applied independently per module with no shared system underneath. The Outlook-composer metaphor on Create Task is well-reasoned alone but imports a different product's visual language into an app simultaneously building its own pill-button system elsewhere.

CLI detector returned clean on all 10 directories, but this is a confirmed tooling blind spot (Razor `@await Html.PartialAsync`/`~/` tilde paths are unresolvable to a static scanner), not a quality signal — verified via a synthetic fixture and a renamed-partial test.

Manual mechanical scan corroborates the "stitched together" verdict with hard counts:
- 6+ separate button-class naming families with no shared base: `.btn-*`, `btn-cancel`/`btn-create`, `et-btn-*`, `mtd-btn-*`, `tr-btn-*`, `um-btn-*`, `btn-login`.
- Inconsistent page-title markup: `<h1>` only on Account + 2 Tasks detail pages; `<h2>`/`<h3>`/nothing everywhere else.
- Zero hardcoded hex colors in inline styles — token system respected where used.

## Overall Impression

The shared shell (topbar, sidebar, tokens.css) is real and works. Below it, Tasks, Records, Reports, and the three dashboards each built their own component vocabulary independently. This is a component-consolidation problem, not a polish problem.

## What's Working

1. Tasks/Edit.cshtml's reassignment flow — readonly OPD-locked fields, progress-carrying reassignment, lock badge blocking reassignment during review.
2. Plain-language status sentences paired with icons in MainTaskDetails, explicitly commented as being for readers who can't rely on color alone.
3. Progressive disclosure done right — collapsed sections preview a summary line before expanding.

## Priority Issues

**[P0] Three independent Kanban/card implementations** (`sa-kcard`, `kanban-card`, MainTaskDetails' own pattern), no shared component. Fix: consolidate into one `_TaskCard` partial. Affects `Views/SuperAdmin.cshtml`, `Views/Shared/_DashboardContent.cshtml`, `Views/Tasks/MainTaskDetails.cshtml`.

**[P1] Token system fork** — `tokens.css` vs `admindashboard.css`'s `--dash-*` duplicate, vs `login.css` reusing `--font-display` for a different font. Fix: consume `tokens.css` directly; rename login's variable. Affects `tokens.css`, `admindashboard.css`, `login.css`.

**[P1] SuperAdmin's two division filters are unsynced** — board and workload table filter independently, risking a misread on resource-allocation decisions. Affects `Views/SuperAdmin.cshtml`.

**[P1] No help/contact affordance in the shell**, despite DTI Laguna having no IT staff. Affects `Views/Shared/_AppTopbar.cshtml`.

**[P2] Review's "Approve" has no confirmation**, while trivial actions elsewhere do. Affects `Views/Tasks/Review.cshtml`.

**[P2] Fragmented button-class system** across 7 naming families for the same Cancel/Save roles. Affects Tasks, UserManagement, Account.

**[P2] Records Timeline shows raw UTC** while every other page converts to Philippine local time. Affects `Views/Records/Timeline.cshtml`.

**[P3] Records Overview / Completion Trend widgets duplicated near-verbatim** into three dashboards. Affects `_DashboardContent.cshtml`, `SuperAdmin.cshtml`, `Employee/Index.cshtml`.

## Persona Red Flags

**Alex (Admin/SuperAdmin):** no bulk actions anywhere; unsynced SuperAdmin filters mislead during triage; reassigning all of a departing colleague's tasks requires opening each one individually.

**Jordan (first-timer Employee):** dashboard shows only 2 of 5 statuses by default; Records' visual language (boxy cards) doesn't transfer to Tasks' (pill composer) if encountered first.

**"Mang Ernie" (older Division Chief):** retention-color legend hides until triggered, backwards for someone who needs the explanation first; Approve has no confirmation; Timeline shows UTC not local time on the one audit-trail page he relies on.

## Minor Observations

- `_TaskList.cshtml` rows are clickable with no visible affordance signaling it.
- `Tasks/Edit.cshtml` (11 inline styles) and `_DashboardContent.cshtml` (7) are the highest remaining inline-style files, not touched this session.
- `Checklist.cshtml` reuses modal-specific class names (`.modal-sub`) on a non-modal page.
- Login's "Forgot Password?" sits in a div named `remember-row` with no remember-me checkbox — leftover naming.
- UserManagement's one-shot temp-password banner has no "show again" path if interrupted.

## Questions to Consider

1. Was there ever one design decision for "what does DTI OneLink look like," or did each module pick its own metaphor independently?
2. Does the SuperAdmin dashboard's density serve a real daily-review habit, or "show everything we built"?
3. Given no IT staff, is duplicating the same widget into 3+ files compatible with the project's own maintenance goals?
